# 02 · Project Submission Guide

Official guide: https://www.spaceappschallenge.org/resources/project-submission-guide/
Our summary and checklist. Hackathon rules and times: [01](01-Competition.md). How to credit and disclose AI: [03](03-Citation-and-AI.md).

## Key facts
- **Opens:** Sat Nov 14, 09:00 local (Haifa). **Closes:** Sun Nov 15, **23:59** local. Anything saved or submitted later is not judged.
- **The project page is what judges review.** More detail = better scores. The demo counts mostly for *Presentation*.
- **Everything in English** (page and all linked material). A video may be spoken in Hebrew only with English subtitles. Slides: English only.
- **Hard limits:** video ≤ **30 s**, or slides ≤ **7** (incl. title and intro). Over the limit = **not eligible for global judging**.
- **At least one NASA data source** is required for a Global Award.
- **No images, video or audio of anyone under 18.**
- Edit and resubmit as often as we like until the deadline. **Only the last saved submission is judged.**
- All team members must be confirmed at the same Local Event (Haifa).

## Where to edit
Profile icon (top right) → **My Team** → **Project** tab (appears Nov 14, 09:00) → blue **Edit**.
- **Save Progress** often. Changes are visible only to the team until submitted.
- Turn the edit **Lock** ON while editing. Someone else can still break the lock and overwrite unsaved work, so **one editor at a time, say so in the team chat.**
- Uploads: images only (JPG, PNG, GIF, ≤ 10 MB). **No video or document uploads**: link them instead.

## Form fields
| Field | What to write | Our source |
|---|---|---|
| **Project Name** | Short title | Team decision |
| **High-Level Project Summary** | What we built, how it answers the challenge, why it matters | README + git history |
| **Link to Project Demo** | Public link to the 7 slides or ≤ 30 s video | Slides / YouTube |
| **Link to Final Project** | Public link: site, repo, etc. No login | Hackathon repo + hosted app |
| **Detailed Project Description** | What it does, how it works, benefits, goals, tools / languages / software | README + method docs |
| **Use of Super Intelligence (SI)** | Which AI tools and how. Data collection only, **judges don't see this answer** | [03](03-Citation-and-AI.md#ai-disclosure), [04](04-Sources-and-tools.md) |
| **NASA Data** | Specific NASA data and resources used | [04](04-Sources-and-tools.md), `ACKNOWLEDGMENTS.md` |
| **Space Agency Partner Data and Other References** | *All* data, code, text, images, tools, even open source. CSA is a partner agency | [04](04-Sources-and-tools.md), `ACKNOWLEDGMENTS.md` |

These cover our six parts in [01 · What to submit](01-Competition.md#what-to-submit): limitations go in the Detailed Description; AI disclosure splits into the SI field + visible marks in the project (below).

## AI ("SI") rules: affects us
SI = Super Intelligence, the site's word for AI tools (ML, chatbots, image generation, LLMs). Allowed, as a tool. Not to come up with the idea.
- **Images and videos made by AI:** a **visible watermark** saying so.
- **Code and data made with AI:** say so in **descriptive text and metadata** (README, file headers, commit trailers already say `Co-Authored-By: Claude`).
- **Audio:** say so in text and metadata.
- AI output must not use or change **NASA branding** (logos, flags, mission identifiers).
- Judges don't see the SI answer, but **do** see the marks in the project and judge originality and intent from them. So be clear and honest in the README.

## Links: make them work for judges
- Host video/slides/docs on YouTube, Google Drive, GitHub, OneDrive, Dropbox… **Public, no login, no permission request.**
- **Test every link in a private/incognito window** (or ask a teammate) before submitting. If judges can't open it, it isn't judged.
- New website? Optional but recommended: request a **FortiGuard Web Filter Classification** (form linked from the official guide) so filters don't block judges. Category: e.g. *Education*, *Reference* or *Web-based application*. Company Name: `N/A`.

## The demo
Pick video or slides early and name one owner. Tell the story to someone with no background: strong visuals, few words, readable fonts.

**Video (≤ 30 s), suggested timeline:**
| Time | Content |
|---|---|
| 0:00 | Who we are: names, team name |
| 0:02 | The challenge and why we chose it |
| 0:05 | Project title + tagline |
| 0:10 | How it works: screens, the user's experience, how NASA (and partner, e.g. CSA) data makes it possible |
| 0:20–0:30 | The future: what it can do for people and the world |

**Slides (≤ 7):** must show team name, member names, the chosen challenge; an image of the project; the user experience; how NASA / space-agency data makes it possible.

Inspiration: past global winners' Project tabs → Demo section (link in the official guide).

## Submitting
1. All required fields filled (otherwise the button won't submit).
2. Tick **Terms and Conditions**.
3. Tick **Confirm All Work is Original**.
4. Click **Submit for Judging** → check the green banner / confirmation appears.
5. Changed something later? **Save and submit again.**

## Certificate
After submitting: Profile → **Participant Information** → *2026 NASA Space Apps Challenge* → **Download Participant Certificate** (PDF, Letter size, from a computer). Name comes from **Full Name** in the profile; fix it there any time. Problems: web@spaceappschallenge.org.
